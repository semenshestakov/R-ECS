# Команды

[🇬🇧 English](../../en/guides/commands.md) · [⬆ Документация (RU)](../README.md)

Команды откладывают **структурные изменения** — создание, уничтожение или
переформирование сущностей — до безопасной точки между кадрами. Это позволяет
системе запрашивать изменения во время итерации `view`, не повреждая хранилище,
по которому она идёт.

Поставьте команду в очередь через `registry.Commands().Push(...)`; она
выполнится при сбросе команд в `Update()`.

```cpp
registry.Commands().Push(/* команда */);
// ...пока ничего не произошло...
registry.Update();   // здесь команды сбрасываются
```

## CreateEntityCmd

Откладывает создание сущности из префаба с необязательным колбэком, получающим
новую `Entity`:

```cpp
ecs::PrefabEntity prefab;
prefab.AddComponent<Position2d>(3.f, 4.f);

registry.Commands().Push(ecs::CreateEntityCmd{
    std::move(prefab),
    [&](ecs::Entity e) { spawned = e; }      // необязательный колбэк onCreated
});

registry.Update();   // сущность создана; колбэк вызван
```

Префаб можно передать по rvalue (перемещение) или как
`std::shared_ptr<PrefabEntity>`, если хотите переиспользовать его. Колбэк удобен
для захвата итогового хэндла, ведь id неизвестен до сброса.

## DeleteEntityCmd

Откладывает уничтожение; необязательный колбэк выполняется, **пока сущность ещё
жива**, прямо перед уничтожением. Удаление уже мёртвой сущности молча
пропускается.

```cpp
registry.Commands().Push(ecs::DeleteEntityCmd{
    entity,
    [&](ecs::Entity e) { logDeath(e); }      // необязательный колбэк onDeleted
});
registry.Update();
```

## AddComponentsCmd

Откладывает добавление (или перезапись) одного или нескольких компонентов. Типы
компонентов выводятся (CTAD), так что вы просто перечисляете значения:

```cpp
registry.Commands().Push(ecs::AddComponentsCmd{ entity, ecs::Health{77.f} });

registry.Commands().Push(ecs::AddComponentsCmd{
    entity, Health{50.f}, Damage{15.f}, Speed{3.f}      // несколько сразу
});

registry.Update();
```

Поведение повторяет `EntitiesManager::AddComponents`: существующие компоненты
перезаписываются, новые мигрируют сущность в новый архетип, rvalue-аргументы
*перемещаются*, а lvalue *копируются*. Команда на мёртвую сущность — no-op.

> Значения компонентов хранятся внутри команды до сброса, поэтому они должны быть
> copy-конструируемыми (очередь держит их в `std::function`).

## RemoveComponentsCmd

Откладывает удаление. **Типы** компонентов — параметры шаблона, без значений:

```cpp
registry.Commands().Push(ecs::RemoveComponentsCmd<Health>{ entity });
registry.Commands().Push(ecs::RemoveComponentsCmd<Health, Damage>{ entity });
registry.Update();
```

Удаление последнего оставшегося компонента уничтожает сущность (сущность на
архетипах не может быть пустой).

## CookCmd

Создаёт сущность из [рецепта](./recipes-and-cooking.md), при желании вызывая
события префаба. Разобрано в [Рецепты и «готовка»](./recipes-and-cooking.md):

```cpp
registry.Commands().Push(ecs::CookCmd<Player, PlayerRecipe>{ PlayerRecipe{} });
```

## Осмотр очереди

```cpp
registry.Commands().size();    // сколько команд ожидает
```

После сброса очередь снова пуста. Команды, поставленные во время сброса,
выполняются на следующем кадре, поэтому цепочки работы предсказуемо
распределяются по кадрам.

## Команды против немедленных вызовов

| | Немедленно (`registry.Entities()....`) | Отложенно (`registry.Commands().Push(...)`) |
|---|---|---|
| Когда выполняется | сейчас | при сбросе в следующем `Update()` |
| Безопасно в цикле `view` | ✗ (может инвалидировать итерацию) | ✓ |
| Сразу знает id новой сущности | ✓ | только через колбэк после сброса |
